01 / Research question

How do large language models choose between competing online course providers?

When a person asks an AI assistant to recommend an art course, the answer depends on which provider features the model attends to — price, reviews, credentials, description quality, or page structure. This MSc experiment treats each model as a decision-maker and measures, across many repeated runs:

  • Which course provider wins when five deliberately different pages are shown side by side
  • What the model says drove its choice — a six-question exit interview covering price, reviews, credentials, description, clarity, and an open reason
  • What the answer costs — tokens, latency, and dollar cost per run, per model

The comparison is deliberately restricted to low-tier (cheap) models, because the practical question for consumers is what a cheap API call buys you.

02 / Method

  1. The model receives all five course pages as full HTML in a single prompt and must pick exactly one provider.
  2. Immediately after choosing, the same model answers a five-point Likert exit interview plus one open question about its choice.
  3. Every run is appended to a CSV with 37 columns: model, provider, tier, condition page, run number, chosen page, page order, all six interview answers, the model's choice reasoning verbatim, token counts, dollar cost, latencies, attempt counts, and the winning page's feature values.
  4. Runs are resumable — a crashed or interrupted collection continues from the first missing (model, page, run) slot instead of repeating completed work.

Collection runs programmatically from src/run_experiment.py (no manual clicking), logs every invocation to logs/, and is hard-capped by a ${{ budget|int }} budget guard read from config.yaml.

05 / Dataset & integrity

  • course_choice_dataset.csv — the final dataset: every collected run, 37 columns, one row per (model, page, run).
  • dataset_run_logs.zip — the raw collection logs: per-run timestamps, costs, retries, and errors for every model block.
  • Live CSV — the operator's working results.csv, updated as new runs are recorded.

Costs are computed from real provider usage tokens, not estimates. Every row carries its own token counts and dollar cost, so the total spend can be recomputed from the CSV alone. Budget guard: ${{ budget|int }} cap per config; the full collection ran well under it.
